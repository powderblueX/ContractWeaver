# 需求交付状态与剩余验收

截至 2026-10-22，定位为人工审核的合同填写 multi-agent 开发项目；不能将“开发闭环已实现”表述为“所有需求已全面验收”。

| 需求 | 当前实现 | 尚缺的验收或能力 |
| --- | --- | --- |
| 协商记录驱动的 multi-agent | 分析、提取、独立复核、全合同覆盖四个角色，独立上下文，服务端协调版本与人工审核 | 真实服务商全链路、事实准确率、冲突识别与成本评测；覆盖检查不等于无遗漏认证 |
| 用户明确点名合同 | 原名与引用保留、原文显式正向请求兜底、精确名称优先；被拦截原件仍显示原因 | 同义名、简称、多版本、先要求后取消等会话歧义不能承诺完全判断正确 |
| 模板检索及自主选择 | BM25/RRF、可选向量路、最多五份候选、完整模板库浏览 | 标注数据集上的 Recall/NDCG 和实际用户选择评测；未实现模型重排 |
| 使用原始 Word 而非维护旧占位符库 | 自动定位结构字段、LLM 提议、用户确认、文字节点写入、媒体保留检查 | 567 份中 494 份通过结构审计、73 份仍拦截；不保证语义空白无遗漏或最终版面正确 |
| 分层、命名与维护 | 路由、工作流、领域模型、Agent、文档引擎、仓储和前端 feature 分层；配置及关键边界注释 | 架构质量不是一次性“完成”认证，后续功能应继续遵守边界 |
| 密钥及配置 | 后端 `.env`/环境注入、类型校验、不进前端；Compose secret 不进入镜像 | 历史密钥轮换、生产 Secret Manager、日志脱敏和渗透/依赖安全验收 |
| 新手本地运行 | 双语 README、Windows 专用手册、虚构纪要及验收清单、初始化和独立启动、项目级停止/可选环境清理；Linux/macOS Bash 启动脚本 | Windows 启停与保留数据已实测，其他平台静态检查不等于实跑；不承诺系统/浏览器绝对零痕迹 |
| Docker | 两端 Dockerfile、Compose、Nginx 同源代理、健康检查和持久化卷 | 尚未完成本机容器构建与实跑，基础镜像摘要和部署依赖锁定需随正式发布维护 |
| GitHub 公开发布 | 新项目命名、文档、忽略规则、旧占位符资源清理 | 第三方合同/模型/索引资源的授权核对、开源许可证选择；当前没有擅自添加覆盖第三方资源的许可证 |
| 生产运行 | 单实例 SQLite、所有权校验、版本冲突保护、生成历史 | HTTPS、限流、备份恢复、监控、容量；多实例需要集中数据库/任务队列/文件存储 |

不在当前实现范围：OCR、图片内填写、扫描 PDF、音频转写、自动签署、自动法律适用性认证、无人审核生成。增加这些能力需要单独设计与验收，不应通过解除安全限制来冒充支持。

发布前最低验收顺序：真实模型非敏感样例 → 目标模板业务与版面 → 各平台启动与容器实跑 → 安全与备份恢复 → 资源授权及许可证。具体检查结果见 [validation.md](validation.md)，运行步骤见 [deployment.md](deployment.md)。
