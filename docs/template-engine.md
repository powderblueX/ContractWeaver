# 原始合同模板引擎与验收边界

## 为什么不让 LLM 直接改写整份 Word

LLM 适合从协商记录提取候选值、解释依据和检查冲突，但无法保证不遗漏字段、不改动固定条款、保留全部 Word 结构。即使使用结构化输出，事实错误仍然可能发生，参见 [Structured Outputs 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)。

Word 段落包含多个具有不同格式的 run。整体赋值 `paragraph.text` 会重建内容并丢失 run 格式，参见 [python-docx 文本 API](https://python-docx.readthedocs.io/en/latest/api/text.html)。因此本项目不采用整份文本生成后覆盖 Word 的方案。

## 当前实现

2026-10-22 修复：格式属性中的制表位不再作为正文；冒号/制表符/下划线组成的同一空白合为一个字段，条款编号后的对齐空格不生成填写项。年月日分格附带数字范围和日历校验；括号内“是/否、有/无”作为枚举字段，未知时可恢复原选项。大写金额使用固定单位约束，避免“叁仟元整元”。确认、预览和导出都会校验这些约束。模型上下文唯一标出当前填写位置；全合同覆盖检查补充逐字段复核的视野，但不保证无遗漏。此次引擎指纹升级要求旧任务重新载入模板并审核，参见[保管合同检查报告](custody-export-review.md)。

1. 模板库只扫描原始 `resources/contracts/templates/{Ministerial,Regional}/*.docx`。下载返回未改动的原文件。
2. `app/documents/template_slots.py` 在内存中将可定位的空白编译成内部字段。包含连续下划线、下划线空白 run、段内连续空格、空白表格单元、冒号后的候选位置；原件已有 `{字段名}` 仍支持。
3. 自动字段按段落和出现顺序区分位置，重复金额或日期不自动共用一个值。字段上下文包含附近文字；表格包含列号、首行和当前行。合并表格的列号是 XML 单元顺序，不等于视觉网格列号。
4. 提取 Agent 仅返回这些字段的候选值及原文证据；复核 Agent 检查映射和协商状态。服务器验证引用，用户审核每个位置。多召回的排版空白或标题须明确注明留空原因，不能直接消失。
5. 预览和生成重新读取同一个原件并编译。只修改 XML 文字节点，不整体赋值 run 或 paragraph，保留图片、链接和框体；明确留空的自动字段恢复原空白。原件已有显式占位符留空时保留原标记。
6. 导出前逐段比较实际文本和预期替换文本，并比对图形结构及媒体指纹；任何已确认位置未成功写入时拒绝保存。审计还会保存并重新读取 DOCX 检查文字与媒体。文件指纹和引擎版本指纹防止旧位置映射复用，旧任务需重新选择模板。

模型不能添加模板字段、替换固定条款或跳过人工确认。没有模型配置时仍可手工填写已识别字段。

## 保守拦截与已知缺口

嵌入对象、内容控件、旧版表单或邮件合并域、外部导入 XML、未接受的修订、实际脚注或尾注，以及无法一致同步的兼容分支仍硬拦截。详情返回 `fillable=false` 和原因，前后端均拒绝选择，原件仍可下载。

图片、图形、图表不再一律拦截：其内容保持原样，不执行 OCR 或图片内填写，生成必须额外提交 `visual_review_acknowledged=true`，确认用户已核对视觉内容并会检查导出排版。纯 VML 分隔线不需要额外视觉确认。Word 文本框中的文字纳入扫描和填写；新版/旧版兼容分支只有在完整段落文字一致时才合为一组审核字段，并同步写入，预览不重复显示。不同或嵌套文本框分支仍拦截。长文字可能溢出框体，文字预览不能证明版面正确。

Word 自动生成的脚注分隔符不属于实际脚注。正文和已有普通、首页、奇偶页页眉页脚均参与扫描，不会为了读取而新建页眉页脚。合并单元格的延续区不是独立字段；若延续区藏有文字则拦截维护。

结构识别不是完整的版面理解：单个普通空格、空白段落是否代表填写区域、勾选项、删除不适用条款、附件是否齐全等仍需人工判断。冒号后的固定内容、用于排版的连续空格会造成假阳性。长合同可能有较多候选字段，费用随字段批数增长。

## LLM 收到的到底是什么

不是原始 Word 文件。当前请求是带行号的协商记录、结构字段及附近文字/表格上下文；复核角色还会收到提取提议。模型返回 JSON 候选值与引用，由用户审核后再由文档引擎写入 DOCX。内部临时标记只是定位机制，不需要维护旧占位符模板库。

DeepSeek Flash 的[官方视觉接口](https://api-docs.deepseek.com/guides/vision/)支持图片输入，但本项目当前适配器只发送文本，不调用视觉/OCR，也没有让模型直接编辑 Word 的工具。不能把文档引擎的支持范围归因于模型不支持填写。增加视觉能力仍需坐标到 Word 结构的映射、格式保护和人工验收，不应直接放开任意整篇重写。

不能宣称全部模板均已完成业务参数化，也不能用“有占位符”或“JSON 合法”证明不漏项。用户需要对照原件核对扫描范围，导出后仍需在 Word 中核验布局、金额、选项、签章及附件。当前文字预览不等于版面预览。

## 整库审计

在后端环境执行：

```powershell
python -m app.cli.audit_templates
```

不调用模型、不改原件、不落地测试合同。报告包含扫描数量、字段数量、支持/拦截情况和错误。对于支持的模板，在内存中给每个字段赋唯一哨兵值，验证字段均能写入且段落文本与预期替换完全一致。

`verified_roundtrips` 是结构写入校验，不是“业务无遗漏”的认证。报告中的 `unfillable` 项继续保留在库中供下载；不能绕开拦截强行生成。具体本次结果见 [验证记录](validation.md)。

## 正式模板验收清单

- 用 Word 打开原件，对照所有候选字段，检查空白、表格明细、选项、签章及附件，补齐未覆盖位置；对无法安全定位的模板维持拦截。
- 每类字段用不同测试值填写，检查没有错误复用金额、日期、当事人或明细行；检查跨 run、页眉页脚、合并单元格、长文本换页。
- 用真实协商记录测试初步报价、最终约定、否定陈述、冲突及缺失，确认不会编造值。人工决定留空或修改。
- 重新运行离线审计和端到端测试，记录模板文件指纹、验收者及日期。结构更新后必须重新验收。
- 原件维护必须独立验收，不能因清理历史占位符库而将原件视作自动通过。

当前选择是“原始模板 + 可审查结构字段 + LLM 提取 + 人工确认 + 程序写入”，而不是继续人工维护五万多个历史占位符，也不是让模型任意生成合同。

历史占位符库已按仓库所有者要求删除；删除前确认 1134 个 DOCX/JSON 资源与 Git 历史一致，可从历史恢复。原始模板、业务关键词及索引仍保留。当前自动识别是结构扫描，不是视觉版面理解；删除备份不会增加支持模板数量，也不会解除复杂结构拦截。
