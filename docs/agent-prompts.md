# Agent 任务提示词：如何理解记录并输出可填字段

这里的“处理指导”指 prompt 说明输入、分解任务、约束映射并定义结构化输出，不是要求服务商公开内部 CoT。**不依赖 thinking 模式，也不需要 LangChain/LangGraph 才能生效。**

统一维护位置：`backend/app/agents/prompts.py`。主控与四个专业 Agent 均直接引用这里的规范；运行记录包含 `prompt_version`，便于区分采用了哪版任务说明。修改规则时同步更新版本并执行回归测试。

每个 prompt 都包含共同安全边界、角色目标、输入说明、处理顺序和输出契约。实际请求把任务说明与动态 JSON Schema 放入 system message，把原文及本次字段数据放入单独的 user JSON message；原文和模板内容不能更改系统任务。字段短编号和枚举由当前模板动态生成，不靠 prompt 硬编码模板字段。

| Agent | 如何处理 | 输出 |
| --- | --- | --- |
| 主控协调 | 读取当前允许动作、分析/检索/复核观察和剩余预算，选择工具、修正目标或交人工 | `action`、短编号目标、检索词或补充问题，以及简短依据 |
| 记录分析 | 区分交易角色、共识、提议、否决及未定事项；保留明确点名的模板原名和证据 | 交易摘要、检索词、未定事项、模板请求 |
| 字段提取 | 按槽位上下文寻找原文依据，处理行列、日期分格、金额和固定单位，缺失不猜测 | `fields`：编号、值、状态、证据、备选、备注 |
| 定向修正（提取角色） | 结合旧候选及复核问题重新核对原文，只修正主控指定的有关字段 | 新的候选 `fields`，仍需再次校验和复核 |
| 独立复核 | 重新对照原文及槽位约束，检查提议误作共识、角色错配、映射和格式错误 | `findings`：字段编号、具体问题和严重程度 |
| 覆盖检查 | 跨字段检查明确约定的遗漏与可见模板文义冲突；不把候选上下文冒充完整 Word | `gaps`：问题、逐字证据、建议人工检查位置 |

例如，记录明确写“整个保管期间费用共3000元”，模板位置为“大写：[当前填写处]元”，类型为 `money_upper`，则候选值应为“叁仟”，不是“叁仟元整”，同时引用原文并备注格式转换。没有账号就返回 missing，不把会议日期当签约日期，不把后来尚未获得同意的报价覆盖已明确共识。

服务端仍执行 Schema/编号/证据/类型约束校验，独立复核后交由用户决定；prompt 本身不保证输出正确。运行摘要是可选的简短解释，不是写入合同的字段值或人工确认。测试使用假模型与模拟 HTTP，验证任务规范确实进入请求、原文与规则分离、槽位约束和短编号保持一致；并不能据此声称真实模型的提取准确率已通过验收。

思考模式是另一项独立配置。若目的只是上述任务指导，保持已有 `LAW_LLM_THINKING_MODE=disabled` 也可正常使用，无需因为这套 prompt 而开启或提高推理强度。
