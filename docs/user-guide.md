# 使用引导、等待状态与结果判断

## 按页面顶部的“下一步”操作

1. 保存协商记录后，点击“分析记录并推荐模板”。这一步才会调用模型；右上角“已配置模型”不代表已经发过请求。
2. 查看候选原件，确认后选择合同。选模板不会自动触发收费提取；顶部会提示下一步。
3. 点击“按模板提取并复核字段”，观察旋转加载、已等待时间、真实请求/响应次数与批次状态。不必重复点击。
4. 先核对有提取值的项目，再处理缺失、分歧和表格明细。用户审核后才用于导出，不会把模型值直接当成正确答案。
5. 第一轮信息不全时，可点击“一键忽略未确定空白”，确认统一原因后处理整个合同的空白项，不受筛选和分页影响。已有值、已审核项和未保存修改不会被覆盖。有内容的分歧仍需核对。以后取消对应字段的“保留空白”即可补充；至少确认一项非空值才可导出。留空只用于待完善草稿，不代表合同可签署。也可展开批量工具，只选择部分空白处理。
6. 全部位置确认或明确留空后，进入最终预览。此时按段落和表格显示已审核内容，不暴露 Word 内部定位编号。预览不是 Word 页面渲染，下载后还需核对排版。

“170 个候选位置”不等于 170 个必填业务问题，其中可能包含重复表格行和排版空白。模型没有把值填满也不等于没有调用；应结合响应计数、失败原因和原文判断。

## 怎么看进度

主控会依据工具结果选择继续检索、定向修正、请用户补充或交回审核。进度卡中的能力清单不是固定顺序，实际步骤会显示“主控选择”和修正目标数。默认每次分析最多检索 3 次，每批最多定向修正 1 轮；会增加模型调用，不保证每轮都能修好。主控问题与降级说明显示在任务顶部，未知内容仍可暂留空；修正候选不会自动确认，必须由你审核。

- 记录分析和模板检索没有可验证的百分比，使用不定进度动画，不模拟 10%→100%。
- 字段处理显示每批“排队 / 提取中 / 复核中 / 完成 / 失败”，进度是已经处理的批次数（含失败），不是提取准确率或人工审核完成率。
- 实际模型请求数在 HTTP 请求发起时计数，成功 HTTP 响应在收到 2xx 时计数，网络/非 2xx 失败另计；结构化重试会增加次数。HTTP 成功不等于 JSON 合法，更不等于事实正确。
- 失败批次单独显示原因，可重试失败批次，已人工审核项不被失败重试覆盖。重新提取全部字段会提示覆盖人工结果。
- 前端每秒读取一次当前任务的受保护进度接口。重新打开尚在同一后端进程运行的任务会继续观察，轮询失败有独立提示，不代表主请求已失败。

执行进度卡可展开“Agent 执行计划与决策摘要”。这是实际步骤与简短解释，不是模型内部完整思维链。Harness 每任务保留最近 20 次 SQLite 运行日志（含失败），并限制请求数、步骤数、总时间和输入大小；另有最多 200 条内存实时记录。服务重启后仍可查看持久日志，运行期限到达后显示中断，但未提交结果可能丢失，需要用户重新执行；它不是后台任务队列或任意节点自动续跑系统。旧任务没有 HTTP 计数时不会补造历史次数。配置及架构见 [agent-harness.md](agent-harness.md)。

## 邮箱登录

注册与登录统一使用“邮箱 + 密码”，不再填写用户名，也不提供用户名登录。已有账户仍使用原邮箱和密码，数据不删除。数据库旧用户名列只为兼容旧表结构保留，注册时由系统生成内部值，不作为用户身份输入或公开资料。

## 本轮字段映射调整

提取/复核模型只接收当前批次的短编号（如 `f001`）、可读名称、唯一的“当前填写处”与类型约束；响应经过编号枚举与结构校验，再恢复成 Word 定位标识。未知编号进入有限格式重试，不绕过字段或引用校验。2026-10-22 的重复空白、日期分格和选择项修复改变了引擎指纹：旧任务必须点击顶部“重新载入当前模板并开始审核”，然后重新提取审核。原记录和历史文件保留，但旧文件不会自动修复。

年月日分格只填写数字；带“元”的大写金额位置只填写“叁仟”等数额，不重复写单位。日期越界、无效日历日期和不在允许列表内的选项不能确认或导出。有复核警告的候选不进入普通批量确认，需逐项处理。最后的全合同覆盖 Agent 检查已约定却未填入的事实，引用仍由服务器核验；结果是提取时的快照，修改后仍需人工对照。失败、引用不可验证或上下文超限会明确显示，不伪装为通过。

短编号降低了长定位名被模型改写的风险，但不承诺每次模型都返回正确结果。真实服务商的准确率与成本仍需用户验收。读取或重试真实记录会向所配置服务商发送记录与字段上下文并可能计费。
